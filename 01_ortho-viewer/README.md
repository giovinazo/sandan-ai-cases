# 01_ortho-viewer · 정사영상 현황지도(평면·입체)

무인항공촬영 성과품(정사영상·수치표면모델)을 담당자 PC에서 **더블클릭으로 여는 지도**로 만드는 도구입니다.
서버·인터넷·GIS 프로그램 없이 브라우저만으로 열리고, 누른 자리의 표고와 좌표, 거리·면적·건물 높이를 잽니다.

> 이 폴더에는 **코드와 가상 예시자료**만 들어 있습니다. 실제 정사영상·DSM·점군·측량성과·지적·건물윤곽은 넣지 않았습니다.
> `sample_data/`의 영상·표고·도형은 모두 파이썬으로 합성한 **가상 자료**이며, 좌표는 서해 해상의 임의 위치(EPSG:5186 E 100,000~101,000 · N 450,000~450,800, 실제 육지 아님)입니다.

처리 흐름: 원본 GeoTIFF(EPSG:5186) → 좌표계 변환(EPSG:3857, gdalwarp) → 피라미드(gdaladdo) → XYZ 타일(gdal2tiles --xyz) → DSM으로 음영기복·표고 격자 → 화면 파일(build.py·build_3d.py)

## 1. 무엇을 하는 도구인가

| 화면 | 하는 일 |
|---|---|
| **평면지도.html** | 정사영상 타일 위에 음영기복(4단계: 끔·연하게·진하게·음영만)·사업경계·블록·현황 건물·도로·구거·등고선(1m)·지적을 켜고 끔. 지도를 누르면 **지반고·표면고·평면직각좌표**. 거리·면적 재기 |
| **입체지도.html** | 정사영상을 씌운 지형을 돌려 봄(three.js). **표면/지반 전환**, 높이 과장 1~5배, 색(사진·지장물 높이·분류), 사업경계·키맵. **측정**: 건물(면적·가로세로·용마루·처마·부피)·높이·면적·거리, 측정 목록 CSV 저장, 근거 설명 탭 |

- 두 화면은 서로 오가는 단추로 이어져 있습니다.
- 라이브러리·자료·표고 격자를 모두 화면 파일 안에 담아, `file://`로 열어도 동작합니다(외부 요청 0건).
- 다른 PC로 옮길 때는 산출 폴더(`output/.../지도`)를 통째로 복사하면 됩니다.

## 2. AI(Claude)가 한 일과 사람이 검증한 일

**AI가 한 일**
- GDAL 처리 순서 설계와 명령 조합(gdalwarp → gdaladdo → gdal2tiles, gdaldem hillshade)
- 화면 빌더(평면: Leaflet, 입체: three.js) 코드 작성, 표고 격자를 base64로 화면에 담는 방식 고안
- 평지에서 음영기복이 안 보이는 원인 진단(그늘 값이 좁은 폭에 몰림)과 계조 펴기·합성 방식 변경
- 거리·면적을 웹메르카토르가 아닌 평면직각좌표(EPSG:5186)에서 재도록 좌표 변환 구현, 입체 화면용 2차식 변환과 역변환(뉴턴법)
- 검증 스크립트 작성(표고·좌표·면적 대조, 건물 위치 대조군 시험, 윈도우 파일명·오프라인 점검)
- 이 공개판에서: 가상 예시자료 생성기, GDAL 없이 도는 대체 경로, 설정 파일 분리

**사람이 검증·결정한 일**
- 목적·범위 결정: 내부 업무 참고용, **인터넷 공개 안 함**(고해상도라 사유지 마당·차량까지 보임)
- 원자료 선택: 여러 판의 도면 중 어느 파일을 쓸지, 화면에 띄울 것과 뺄 것(예: 표고점은 누르면 나오므로 뺌)
- 화면 조작 확인과 지적: 입체 화면 끌기 방향이 지도와 반대라는 지적 → 지도식 조작으로 수정
- 수치 대조 결과 판단(원 사업 기준)

| 확인 | 결과(원 사업) |
|---|---|
| 표고: 화면 값 대 원본 DSM 직접 표본 9곳 | 중앙 0.01m · 최대 0.05m 차이 |
| 좌표: 화면 평면좌표 대 GDAL 변환 9곳 | 차이 0.00cm |
| 면적: 블록 하나를 둘레 49점으로 찍어 잰 값 대 조서 | -0.059% (구면 근사로 재면 +0.126%) |
| DSM 대 검사점 | 중앙 +0.021m · RMS 0.046m |
| 건물 윤곽 위치(대조군 포함) | 제자리에서 둘레보다 0.5m 넘게 높은 비율 75.1%, 50m 밀면 27.7%로 떨어짐 |
| 윈도우·오프라인 | 외부 요청 0건, 파일명 금지문자·예약어 0건, exFAT USB 복사 후 동작 확인 |

이 공개판 자체는 예시자료로 두 경로(GDAL 없음·GDAL)를 끝까지 돌려, 두 경로의 표고 격자가 같은 자리에서 중앙 0.000m·최대 0.1m(격자 반올림 한 단위)로 일치함을 확인했습니다.

| 항목 | 내용 |

| 패키지 | `pip install -r requirements.txt` (numpy, Pillow) |

## 5. 예시자료로 돌려 보기

맥·리눅스:

```bash
cd 01_ortho-viewer
pip install -r requirements.txt
bash run_sample.sh
```

윈도우(명령 프롬프트, 한 줄씩):

```bat
cd 01_ortho-viewer
py -m pip install -r requirements.txt
py scripts\make_sample_data.py
py scripts\tiles_nogdal.py --config sample_data\config.json
py scripts\build.py --config sample_data\config.json
py scripts\build_3d.py --config sample_data\config.json
```

결과: `output/sample/지도/평면지도.html`을 더블클릭합니다(입체는 화면의 ｢입체로｣ 단추 또는 `입체지도.html`).
실행 시간은 합쳐서 10초 안쪽, 산출물은 약 7MB(타일 330장·음영 92장·화면 두 개)입니다.

GDAL이 있다면 같은 예시를 GDAL 경로로도 돌릴 수 있습니다(실자료와 같은 절차):

```bash
bash scripts/make_tiles.sh --config sample_data/config.json
bash scripts/build_dsm.sh  --config sample_data/config.json
python3 scripts/build.py    --config sample_data/config.json
python3 scripts/build_3d.py --config sample_data/config.json
```

`build_dsm.sh`는 osgeo가 든 파이썬을 스스로 찾습니다. 못 찾으면 `PY_GDAL=/경로/python3`로 지정합니다.

## 6. 자기 사업 자료로 바꾸는 법

1. `config.example.json`을 `config.json`으로 복사해 고칩니다(`config.json`은 저장소에 올라가지 않습니다).
2. 도형 자료(JSON)를 `data_dir` 폴더에 둡니다. 수치지형도 DXF가 있으면 `extract_dxf.py`로 뽑을 수 있습니다.
3. GDAL 경로로 타일·음영·격자를 만들고 화면을 만듭니다.

```bash
bash scripts/make_tiles.sh --config config.json     # 정사영상 타일
bash scripts/build_dsm.sh  --config config.json     # 음영기복 타일 · 표고 격자
python3 scripts/build.py    --config config.json    # 평면지도.html
python3 scripts/build_3d.py --config config.json    # 입체지도.html
```

설정 항목(상대경로는 설정 파일이 있는 폴더 기준):

| 항목 | 뜻 | 예 |
|---|---|---|
| `title` · `subtitle` · `footer` | 화면 제목·부제·아래 글 | |
| `crs` | 원자료 평면직각좌표계. 원점·가산값·축척 | EPSG:5186 = 위도 38·경도 127·가산 200,000/600,000·축척 1.0 (서부 5185는 경도 125, 동부 5187은 129) |
| `source.ortho` · `dsm` · `ground` | 정사영상·수치표면모델·지반 표고 GeoTIFF | 지반이 없으면 비워 둠(표면을 두 번 씀) |
| `source.dxf_dir` | 수치지형도 DXF 폴더(extract_dxf.py) | |
| `source.nodata` | DSM 빈값 | -10000 |
| `crop_box` | 자를 범위 [E최소, N최소, E최대, N최대] (crs 좌표, m) | 사업지구 둘레 조금 넉넉히 |
| `ortho_zoom` | 정사영상 타일 배율 [최소, 최대] | 2.96cm 영상이면 [14, 22] (z22 = 3.73cm) |
| `hs_zoom` | 음영 타일 배율 | [14, 20] |
| `hs_z_factor` | 음영 높이 과장 배수 | 평지 4 |
| `grid_res_m` | 표고 격자 간격(웹메르카토르 m). 화면 파일 크기를 좌우 | 2.3873 (땅에서 약 1.9m) |
| `data_dir` · `output_dir` · `work_dir` | 도형 JSON · 화면과 타일 · 중간산출 | |
| `view_3d` | 입체 바탕그림 타일 배율·격자 간격(타일 화소 몇 개마다 한 칸)·그림 한 변·JPEG 화질 | z19·8 → 약 2.4m 격자 |
| `labels` | 표면·지반·지적 설명 글 | |

도형 JSON 모양(없는 파일은 그 단추만 비고 나머지는 동작):

| 파일 | 모양 |
|---|---|
| `base.json` | `bounds`([[남,서],[북,동]]) · `구역계`(GeoJSON Feature 목록) · `블록`(FeatureCollection, 속성 `가구`·`용도`·`면적_㎡`·`획지수`·`색상`) |

## 7. 알려진 함정

**측정·표고**
- **거리·면적은 EPSG:5186 평면에서 잽니다.** 도면·조서와 같은 기준입니다. 구면 근사로 재면 원 사업 블록에서 0.126% 크게 나왔고(평면 기준은 -0.059%), 화면 좌표(웹메르카토르)로 재면 북위 37도 부근에서 약 1.25배 크게 나옵니다.
- **DSM 표고에는 나무·건물 높이가 들어 있습니다. 지반고가 아닙니다.** 성토·절토 산정에 쓰지 않습니다. 지반고는 점군의 지면 점 등으로 따로 만들어 `ground`에 넣습니다.
- 지반고는 숲·비닐하우스 밑처럼 지면 점이 없는 곳을 둘레에서 메운 값일 수 있습니다. 비닐하우스를 ｢높이｣(표면-지반)로 재면 0에 가깝게 나오므로 ｢건물｣로 잽니다.
- 입체 화면은 웹메르카토르 격자라 평면좌표와 축척·회전이 다릅니다. 1차식(아핀)으로 맞추면 4km 범위에서 45cm 어긋나 **2차식으로 맞춥니다**(`build_3d.py` 잔차 출력).

**음영기복**
- **평지 음영기복은 그냥 곱하면 안 보입니다.** 그늘 값이 175~200에 몰리기 때문입니다. ① 높이를 부풀리고(`hs_z_factor`) ② 중앙값이 128에 오도록 **계조를 펴고** ③ 연하게는 **soft-light**, 진하게는 **overlay**로 합성합니다.
- 계조를 편 뒤 빈값은 0이 아니라 **128(중립)** 으로 채웁니다. 0이면 촬영 범위 밖이 시커멓게 덮입니다.
- 음영을 끌 때 합성 방식(`mix-blend-mode`)을 `normal`로 되돌려야 확대가 뻑뻑해지지 않습니다. 확대 중에는 음영 계층을 잠시 감춥니다.

**타일·화면**
- 정사영상 타일 계층은 `updateWhenZooming: true`여야 확대 중 바탕(검정)이 드러나지 않습니다.
- `zoomSnap: 0`에서 리플릿 `redraw()`는 소수 배율(`hs/18.4/…`)을 요청합니다. 부르지 않습니다.
- `file://`에서는 `fetch`가 막히므로 자료를 화면 파일 안에 담습니다. WebGL은 `file://` 그림을 CORS로 막으므로 입체 바탕그림은 `data:`로 담습니다.
- 빌더는 산출 폴더를 통째로 지우지 않습니다(실자료면 타일이 10만 장 가까이 들어 있음).

**원자료 읽기**
- **DWG는 AC1015(R2000) 판만 GDAL로 읽힙니다.** 다른 판은 CAD 프로그램(QCAD 등)에서 DXF로 바꿔 읽습니다. **libredwg(dwg2dxf)는 권하지 않습니다**(빈 껍데기를 낸 사례).
- DWG로 읽을 때 도형 수가 적으면(예: 등고선 15줄) 자료가 없는 게 아니라 **블록을 못 푼 것**일 수 있습니다. DXF로 읽으면 풀립니다. 한글 층 이름이 깨지면 `DXF_ENCODING`을 줍니다.
- 원본이 BigTIFF면 일반 TIFF 파서(Pillow)로 못 읽습니다. `tiles_nogdal.py`는 작은 영상 전용이고, 실자료는 GDAL 경로를 씁니다.
- 맥에서 brew로 GDAL을 깔면 brew 쪽 파이썬에만 osgeo가 들어가고, 그 파이썬엔 Pillow가 없을 수 있습니다. GDAL 단계와 화면 빌더를 서로 다른 파이썬으로 돌려도 됩니다.

**옮기기·배포**
- **경로(폴더)를 옮긴 뒤에는 반드시 다시 만들어 산출물 크기를 견줍니다.** 원 사업에서 한 곳이 자동 치환에 안 걸려 화면 파일이 8,655KB에서 6,314KB로 줄었고(건물·도로·등고선이 통째로 빠짐), 크기 변화로 알아챘습니다.
- 맥이 USB(exFAT)에 쓰면 한글 파일명이 NFD로 바뀌어 윈도우에서 못 찾습니다. 화면이 `한글확인.js`를 탐침으로 읽어 스스로 맞추므로 그 파일을 지우지 않습니다. 맥에서 파인더로 압축해 윈도우에서 풀지 않습니다(한글 깨짐). 폴더째 복사가 안전합니다.

## 8. 유의사항

- **실자료로 만든 화면은 인터넷에 올리지 않습니다.** 수 cm급 정사영상은 사유지 마당·차량까지 보입니다.
- 소유자 이름 등 **개인정보는 도형 자료에 넣지 않습니다.** 지적은 국·공·사유 구분 정도만 씁니다.
- 지적도와 토지조서는 **기준일이 다를 수 있습니다.** 화면에서도 도면 값과 조서 값을 갈라 적고, 조서 쪽 주의 문구(`지적.json`의 `기준.주의`)를 함께 보입니다.
- 화면 수치는 **업무 참고용**입니다. 측량·감정평가·보상 산정을 대신하지 않으며, 근거로 쓸 때는 원자료와 대조합니다.
- 예시자료의 좌표·지형·건물·필지·소유 구분은 모두 가상입니다.

## 9. 원본에서 뺀 것

원 사업 도구 중 다음은 사업 자료에 너무 묶여 있거나 대용량 원자료가 있어야 해서 넣지 않았습니다.

| 뺀 것 | 까닭 |
|---|---|
| 점군 조각 만들기·점군 3D 표시(LAS 수억 점을 100m 칸으로 잘라 보는 자리만 불러옴) | 대용량 LAS 원자료 필요, 압축 묶음 형식에 묶인 코드. 입체지도에서도 점군 단추를 뺌 |
| 점군에서 지반고 만들기 | 같은 까닭. 지반 GeoTIFF가 있으면 `source.ground`로 넣으면 됨 |
| 계획 매싱(승인신청서의 토지이용계획으로 건물 덩어리 세우기)·보고 화면 | 사업 계획 자료 전용 |
| 지적도에 토지조서 붙이기 | 조서 양식 전용, 개인정보가 섞인 원자료를 다룸 |
| 지장물 실측 결과 추리기·조감 사진 렌더 | 다른 작업 폴더의 산출물에 의존 |
