# 사례 3. 관계기관 협의의견 관리대장·대시보드 자동생성

산업단지계획 승인 과정에서 관계기관(중앙부처·도·시·유관기관)이 낸 협의의견과 사업시행자의 조치계획을 용역사가 한글(HWP)로 정리해 PDF로 제출한다. 이 도구는 그 PDF 표를 판독해 **관리대장 엑셀**과 **열람용 대시보드 HTML**을 만들고, 원본 총괄표와 전수 대조한 **검증리포트**를 함께 낸다.

제출본은 판(回次)마다 형식이 바뀐다. HWPX로 오다가 PDF로 바뀌고, 별도 문서였던 재협의가 본표에 합쳐지고, 두 쪽 모아찍기로 오기도 한다. 판이 바뀔 때마다 파서를 손봐 왔고, 그 과정에서 얻은 판독 규칙과 검증 장치를 이 폴더에 모았다. 형식이 같은 새 판은 PDF만 갈아 끼우면 5분 안에 대장·화면·검증이 다시 나온다.

이 폴더의 자료는 모두 **가상 예시**다(가나부·다라청·마바도·가나시·사아공사 등 지어낸 기관, 지어낸 의견 39건). 실제 공문·의견·문서번호는 들어 있지 않다.

## 1. 무엇이 나오나

| 산출물 | 내용 |
|---|---|
| `output/협의의견관리대장.xlsx` | 6시트: 대시보드(KPI·원본 총괄표 대조·기관군×반영여부 차트) · 협의의견대장(전건, 반영여부·쟁점유형 드롭다운) · 기관·부서별 현황 · 미종결관리 · 주요협의의견 · 검증_총괄표대조 |

| `output/협의의견_원문대조표.xlsx` | 대장 의견 ↔ 회신 공문 원문 건별 대조(선택 기능) |
| `output/무상귀속_협의의견_추출.xlsx` | 주제별 파생 추출 예시(키워드는 설정에서 바꿈) |

## 2. AI가 한 일과 사람이 검증한 일

**AI(코딩 에이전트)가 한 일**
- 한컴 PDF 표의 괘선 복원·칸 배정·레코드 경계 규칙을 코드로 작성하고, 판이 바뀔 때마다 깨진 곳을 찾아 고침
- 대장 엑셀·HTML 화면 빌더 작성, 쟁점유형 자동 태깅, 원문 공문 3그램 대조

**사람이 검증한 일**
- **총괄표 전수 대조**: 원본 1쪽 총괄표(부서별 반영·부분반영·미반영·의견없음·미회신)를 따로 판독해 대장과 부서 단위로 맞춘다. 불일치가 0이어야 다음 단계로 넘어간다(`verify.py`가 불일치 시 멈춤)
- **독립 집계**: 레코드 조립 로직을 거치지 않고 상세표 '반영여부' 칸 글자만 직접 세어 대장 건수와 맞춘다. 조립에서 건이 합쳐지거나 쪼개지면 여기서 어긋난다
- 원본 쪽 표본을 눈으로 대조(특히 쪽 경계·병합칸 주변), 원문 공문 대조에서 부분일치·상이로 나온 건을 실물로 확인
- 원본 쪽 오류(총괄표 미집계 행, 총괄표와 상세표의 상태 불일치)는 파싱 오류와 구분해 대장 «비고»에 남김

## 4. 준비물

- Python 3.10 이상
- `pip install -r requirements.txt` (필수: pdfplumber, PyMuPDF, openpyxl)
- 선택: HTML 글꼴을 심으려면 `html_dashboard/fonts/`에 IBM Plex Sans KR woff2 4종(Regular·Medium·SemiBold·Bold, SIL OFL)을 넣는다. 없으면 시스템 글꼴로 보이며 기능 차이는 없다.

예시 PDF에는 실제 원본에서 부딪힌 함정을 일부러 넣었다: 점선 행 구분선, 세로 병합 부서칸·법령칸, 쪽 경계에서 갈린 부서명(`교통정` / `책과-4401…`)과 법령명(`주차장법 및` / `교통영향평가`), 쪽을 넘어간 조치계획, 법령칸 없이 왼쪽으로 병합된 의견칸, `(2차협의)` 재협의 통합, 총괄표가 세지 않은 행 2건, `매장문화재` 쟁점 태깅.

## 6. 자기 자료로 바꾸는 법

1. 제출 PDF를 아무 곳에 두고 `config/project.json`의 `paths.source_pdf`를 고친다.
2. `run_all.py --no-sample`로 돌린다(예시 PDF를 새로 만들지 않음).

**설정 항목(`config/project.json`)**

| 항목 | 내용 |
|---|---|
| `project` | 사업명·판 번호·기준일·협의 시작일·출처 문서명(화면·엑셀 제목에 쓰임) |
| `groups` | 기관군 이름, 역할(`central`·`province`·`city`·`agency`), 논리쪽 범위 |
| `summary` | 총괄표 쪽, 구분칸 별칭, 부처 약칭 표(`org_abbr`), 병기행 규칙(`row_rules`), 재협의 기준값 |
| `names` | 부서·기관 별칭, 도 소속기관 목록, 시 부서칸 앞에 붙는 기관(경찰서 등), 유관기관 분리 정규식 |
| `classify.none_words` | '의견없음'으로 볼 문구 |
| `issues` | 쟁점유형과 키워드(위에서부터 먼저 맞는 하나), 태깅 전 치환표 |
| `parser` | 모아찍기 판정 너비, 괘선 조각 병합 간격, 열 경계 인정 비율, 줄 가르기 단위 등 판독 상수 |
| `extract` | 파생 추출 제목·키워드·확정 건(pinned) |
| `sample_layout` | 예시 PDF 생성기 전용(쪽 크기·열 경계 좌표·글자 크기) |

역할(role)별로 부서를 적는 방식이 다르다.
- `central`: 첫 칸 = 부처, 의견 첫머리 `[부서]` = 소관부서
- `province`: 첫 칸 = 과(또는 `소속기관(과)`), `[팀]` = 팀
- `city`: 첫 칸 = 부서 + 접수문서번호(`도로과-10234(2026.01.10.)`), 근거법령 칸이 따로 있는 5열 표
- `agency`: 첫 칸 = 기관(또는 `기관(본부)`), `[분야]` = 팀

**새 판을 받았을 때 먼저 볼 것**
- 쪽 크기와 모아찍기 여부: 가로로 넓은 장(예: 1190×841pt)이면 두 쪽 모아찍기다. `parser.two_up_min_width`보다 넓으면 자동으로 반을 가른다. 쪽 번호가 바뀌면 `groups[].pages`와 `summary.pages`를 고친다.
- 총괄표: 부서 수·계행 수치가 전 판과 같은지, 병기행(두 부서를 한 행에 적음)이 생겼는지. 생겼으면 `summary.row_rules`에 규칙을 넣는다.
- 재협의가 별도 문서로 왔는지, 본표에 `(2차협의)`로 합쳐졌는지. 합쳐진 판에서 별도 문서를 또 붙이면 그만큼 중복된다. 별도로 왔을 때만 `paths.rehyeobui_pdf`를 준다.
- 전 판 대장과 연번 대응: 행 하나만 빠져도 뒤 연번이 전부 밀린다. `annotations.json`·`extract.pinned`는 연번 + 지문(소관부서 + 의견 앞 20자)으로 잠겨 있어 어긋나면 멈춘다. 멈추면 연번을 재매핑한다.
- 수정 표시: 작성자가 바뀐 문구를 빨간 글씨로 표시해 오면 `pdfplumber` 글자의 `non_stroking_color`로 뽑아 전 판 대장과 대조하면 신규 변경분을 독립 확인할 수 있다.

## 7. 한컴 PDF 파싱 노하우

- **점선 행 구분선 복원**: 한컴 PDF는 표의 행 구분선을 짧은 선 조각 수백 개로 그린다. pdfplumber 기본 표 추출은 이를 선으로 보지 못해 여러 행을 한 칸으로 합친다. `grid.hlines()`가 같은 높이의 조각을 모아 간격 2pt 이하면 이어 붙여 실제 괘선을 복원한다.
- **글자 단위 칸 배정**: 양쪽 정렬 때문에 칸 경계에서 옆 칸 글자가 한 단어로 묶인다. 단어가 아니라 **글자 중심 x좌표**로 칸에 배정한다(`grid.cell_text`).
- **글자 중심 기준 줄 배정**: 줄을 글자 윗변(top)으로 가르면 한자·작은 글자가 윗줄로 튀어 엉뚱한 문장 중간에 끼어든다. `(top+bottom)/2`로 가른다.
- **병합 원점부터 읽기**: 근거법령 칸이 없는 행은 의견 칸이 왼쪽 칸과 병합된다. 고정 열 번호로 읽으면 줄마다 앞 4~5글자가 잘리는데, 남은 문장이 그럴듯해 눈에 잘 띄지 않는다. `build_records.page_bands`가 병합 원점 열부터 읽는다. 판을 올릴 때마다 표본을 원문과 대조한다.
- **두 쪽 모아찍기**: 장 너비가 기준보다 넓으면 `page.crop()`으로 좌·우 반을 갈라 논리쪽 목록을 만든다(`pages.py`). 잘린 반쪽의 괘선·글자 좌표는 한 쪽짜리와 같은 방식으로 읽힌다.
- **쪽 경계 세로 병합칸**: 부서칸·법령칸은 여러 행을 세로로 합친 칸이라 쪽이 바뀌면 글자가 줄 단위로 두 쪽에 갈리거나 다음 쪽이 빈칸이 된다. 어디서 갈리는지는 판마다 다르다(쪽 안 줄 나눔이 한 줄만 어긋나도 바뀐다). 부서명은 총괄표 부서명 목록으로 앞 조각 + 뒤 조각을 맞춰 합치고 앞 조각으로 등재된 건을 소급 수정한다(`normalize.assign`). 법령은 다음 쪽 첫 밴드의 부서칸이 비었거나 조각이면 앞 쪽 글을 물려주거나 이어 붙인다(`build_records.join_law_across_pages`).
- **레코드 경계 규칙**(`build_records`)
  - 반영여부 칸에 값이 있으면 그 건의 종결 → 새 건
  - `○`로 시작하면 새 건, `-`·`*`로 시작하면 앞 건의 하위 항목
  - 협의의견이 비고 반영여부도 없으면 앞 건의 조치계획이 쪽을 넘어온 것
  - 조치계획·반영여부가 모두 빈 칸은 다음 건에 의견이 이어지는 것(부서 표시만 있는 행)
  - `[붙임…]`은 부서 표시가 아니라 앞 건의 연속
- **중첩표 걸러내기**: 의견 칸 안에 작은 표가 들어 있으면 그 세로선이 열 경계로 잡힌다. 표 높이의 일정 비율(`parser.col_min_height_frac`) 미만만 뻗은 세로선은 열 경계에서 뺀다.
- **쟁점 태깅의 부분일치 함정**: `매장문화재`의 `화재`가 재난·안전으로 잡힌다. 긴 낱말을 먼저 치환(`문화재`→`문화유산`)한 뒤 판정한다. 또 공백까지 지우고 찾으면 `산업단지 진출입`이 `…지진…`으로 붙어 오탐이 난다. 개행만 지운다.
- **문서번호 이월 금지**: 번호 없이 새 부서칸이 시작되면 직전 부서의 문서번호를 물려주지 않는다. 물려주면 뒤 부서 수십 건에 앞 부서 번호가 조용히 박힌다.
- **집계 단위**: 총괄표의 '계'는 검토의견 건수, '미회신'은 회신하지 않은 **부서 수**다. 대장은 미회신 부서도 1행씩 올리므로 행 수와 검토의견 건수가 다르다. 반영률은 (반영 + 부분반영×0.5) ÷ (협의건수 − 의견없음 − 미회신).

## 8. 근본 해법

PDF 판독은 임시방편이다. 판마다 형식이 바뀌는 한 파서 수선은 끝나지 않는다. 용역사에 **표준 엑셀 납품양식**(열: 기관군·관계기관·소관부서·접수문서번호·근거법령·협의의견·조치계획·반영여부·차수)을 지시하면 판독 단계가 사라지고 검증만 남는다. 이 도구의 `협의의견대장` 시트 열 구성을 양식 초안으로 쓸 수 있다.

## 9. 유의사항

- **산출물을 직접 고치지 않는다.** 엑셀·HTML은 재빌드할 때 덮어쓴다. 내용은 설정·`annotations.json`에서, 서식은 빌더 코드에서 고친다.
- 대시보드 화면의 건수·비율은 모두 데이터에서 계산한다. 설명글에 숫자를 굳혀 쓰지 않는다(판이 바뀌면 틀린 숫자가 남는다).
- 원본 쪽 오류(총괄표 미집계 행, 총괄표와 상세표 상태 불일치)는 고쳐 쓰지 않고 «비고»에 남긴다. 집계는 원본 총괄표에 맞추고 미집계 행은 구분 «총괄표 미집계»로 둔다.
- HTML에 근거 공문이 통째로 들어가므로 실제 공문을 넣은 화면을 외부에 공유할 때는 공개 범위를 확인한다.
- 원문 대조의 3그램 포함률은 요약·오탈자에 관대한 대신, 부분일치·상이로 나온 건은 반드시 원문 실물로 확인한다.
- `html_dashboard/vendor/`의 pdf.js는 Mozilla의 Apache-2.0 라이브러리다.
